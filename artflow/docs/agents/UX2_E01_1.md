## Review findings handled
1. Seedance 2.5 declares `text/multimodal`, not `image`; a RED capability test caught false rejection of ordinary photos. The helper now understands the declared multimodal mode without a model-name special case.
2. Ordinary video normalization discards photo references outside image mode. Preserving them must not imply they will be used: explicit-mode video gets a compatibility block until image mode is selected.
3. Input-routed adapters already declare `auto_route_by_inputs` internally. Expose this existing capability additively in ModelInfo (default false); do not invent provider-specific frontend IDs. Backend RED tests proved the field was missing, then passed when true/false were surfaced.
4. Existing backend max_refs `or 1` normalization is NOT fixed in this slice. The new client honors explicit zero/unknown values it receives. Wider metadata audit remains E09.
