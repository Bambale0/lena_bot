## Evidence-based findings

1. Ordinary authenticated upload does not persist owner/media ID (`api/web/generations.py`), and derives a content-addressed filename via `save_public_file`.
2. HMAC `apixasset` receipts (`api/trend_assets.py`) do bind user ID and 24-hour issue age; they lack revocation and lasting object identity, encode their URL in nonencrypted base64 and use an unrelated-secret fallback. No pre-existing durable media registry table in `db/models.py`.
3. `Generation.user_id` permits verified own-result lineage only. `ImageSession.reference_urls`, older input_param URLs and Telegram file IDs cannot establish upload ownership.
4. `public_url_is_available` treats external URLs as available for serialization; E01.4.1 correctly offers only limited local existence checking with no external network.
5. Public CDN documentation proposes immutable cache; deletion of storage or database entitlement alone cannot invalidate previously shared public links.
6. No general ordinary Mini App upload retention contract found; feed retention is a different consumer.

## Design review decision

- Reuse `Generation` lineage only as an optional, explicitly authenticated result-adoption route.
- Reuse signed receipts only as an upload handshake, without extending them into permanent identities.
- Recommend separately owned asset registry, unique logical object key, clear lifecycle and owner-checking repository seam. Proposed schema/API are documented but DO NOT exist yet.
- Separate logical access revocation, physical cleanup, and previously public/cached URL exposure.
- Keep older URL-only client behavior and no automatic rights migration. Safety over convenience.
