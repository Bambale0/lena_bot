# [UX2-E01.1] Сохранять материалы при смене модели и блокировать несовместимый запуск

Source: https://github.com/Bambale0/lena_bot/issues/220

## Родитель и состояние
Эпик #210; программа #209. Первый активный шаг: `in_progress`. Blocked by: нет, фундамент #208 выпущен. Base SHA `d97184f4a9587a8237df6504de1fe58ff8142c22`.

## Пользовательский результат
В обычной генерации admin UX2 смена модели/режима не удаляет фото, видео, trim и input IDs. Совместимые настройки сохраняются, неподдерживаемые настройки приводятся к объявленным возможностям с понятной сводкой. При несовместимых материалах все они видны и запуск остановлен до явного исправления; переход обратно возвращает исходные материалы без повторной загрузки.

## Scope
Только обычный React GenerationDraft с `promptId === null` и включённым UX2. Старый UI, шаблонные trend/feed runners и независимые video/audio DOM-enhancer состояния не переписываются. Это НЕ активные/отложенные файлы и НЕ долговременное media storage: в этом шаге несовместимый набор блокирует всю отправку.

## Реализация и порядок
1. Записать RED browser test: загрузить две ссылки на A, выбрать B, убедиться в сохранности массива/DOM; baseline теряет файлы.
2. Добавить pure transition/compatibility helper с immutable результатом. Лимиты брать из текущего ModelInfo, отличать 0/null/missing; использовать существующий backend `max_refs_with_video`, не новый hardcode.
3. Подключить к смене модели/режима. Сохранить совместимые format/quality/duration/resolution/count; не удалять/не обрезать reference arrays. Во время upload/submitting блокировать переключение.
4. Отобразить сохранённые материалы даже при неподдерживаемом новом типе; дать причину и явное удаление/возврат. Нельзя отправить невидимые лишние материалы.
5. Один compatibility result применить и в кнопке, и непосредственно перед `createImage/createVideo`, включая unknown model и поздно изменённые лимиты.
6. Прогнать новые unit/browser, существующие UX2/payment/300 journeys и необходимые backend gates. Осмотреть реальные screenshots. Feature PR с self-review, затем exact-SHA CI/autodeploy/readonly verification.

## Приёмка
- [ ] A→B сохраняет оба референса, порядок и пользовательский текст.
- [ ] При лимите 2→1 массив не урезается; понятная ошибка и 0 generation POST.
- [ ] A→text-only→A возвращает медиа; unsupported upload не предлагается.
- [ ] Видео и trim сохраняются при переходе к модели без video input и обратно; неприемлемый запуск заблокирован.
- [ ] В `max_refs=0` и `max_refs_with_video=0` нет подмены на 1.
- [ ] ID-материалы не стираются; превышение caps видно и исправимо.
- [ ] Режим переключается без очистки, но новая несовместимость объясняется.
- [ ] Upload in-flight не позволяет переключить модель/режим; после completion результат принадлежит исходному draft.
- [ ] Reload восстанавливает полный несовместимый набор, не только допустимую часть.
- [ ] После явного удаления несовместимого материала корректный POST содержит точный оставшийся набор.
- [ ] Старый UI и hidden-template tests не меняют поведение.
