# [UX2-E02] Единый редактор: понятные сценарии, основные и расширенные настройки

Source: https://github.com/Bambale0/lena_bot/issues/211

## Родитель, цель, зависимости
Программа #209. Пользователь создаёт фото или видео в одном понятном редакторе, без обязательного шестишагового мастера и изучения provider-терминов. Приоритет P1. E02.1 опирается на #208 и неразрушающий черновик E01.1 (#210); подключение ролей материалов — на E01.2/E01.3. Полный E01 не является блокером простого редактора.

## Продуктовые решения
Основные действия: создать/изменить фото, оживить фото, создать видео, перенести движение, изменить видео — только при реально поддерживаемом контракте. «Рекомендуемая» модель видна по имени и доступна для замены; нельзя автоматически менять качество/провайдера/цену за пользователя. Быстрый выбор модели остаётся у профессионалов. Бизнес-правила и параметры берутся из backend metadata.

## Вертикальные срезы
- [ ] **E02.1 — фото от идеи до результата.** На одной странице материалы, «Что хотите получить», компактная модель, формат/качество и цена. Начальные пустые поля не окрашены красным; после попытки запуска ошибка рядом с полем и фокус на первом препятствии. Обязательные поля отмечены явно. Существующий image POST и task sheet переиспользуются.
- [ ] **E02.2 — два уровня сложности.** «Основные / Расширенные» редактируют один draft. Seed, несколько запусков, character/audio IDs и provider-specific controls скрыты в advanced, но выбранные нестандартные параметры отражены в краткой сводке. Переключение уровня не сбрасывает ничего. Основной режим делает один платный запуск; количество результатов не называется количеством задач.
- [ ] **E02.3 — видео и движение.** Один редактор с секциями по выбранному сценарию, ролью исходного ролика, форматом и длительностью. «Изменить это видео», «Создать по референсу» и «Перенести движение» не имеют одинаковых payload по умолчанию. Для source-duration стоимость пересчитывается из разрешённого измерения; неизвестная длительность не заменяется выдуманным числом.
- [ ] **E02.4 — выбор модели.** Поиск и сравнение доступных моделей по проверенным возможностям, цене и требованиям. Недоступная модель не исчезает из черновика молча: объяснение, смена вручную. Каталог и фильтры используют тот же capability contract, что форма и API. Не добавляем AI-рекомендацию, автоматически выбирающую дорогую модель.
- [ ] **E02.5 — единая панель запуска.** Действие «Создать за {стоимость} {валюта}» остаётся видно без перекрытия поля клавиатурой. При недостатке средств — сохранённый переход в оплату, а не тупик. Окончательная сумма и model snapshot согласованы с сервером (E07). Таймаут не превращается в повторный платный POST (E04).
- [ ] **E02.6 — редактирование текста и возвраты.** Сохранение описания, расширенных настроек и scroll/focus при просмотре фото, выборе модели, истории и Back. Подсказки описывают ожидаемый результат человеческим языком. RU/EN тексты централизованы; термин «референс» объясняется назначением, а не маркетинговым слоганом.

## Критерии приёмки
- [ ] Фото можно подготовить и отправить без открытия advanced; нет обязательного лишнего wizard.
- [ ] В DOM один владелец draft и одна основная submit-команда.
- [ ] Все параметры активной модели доступны в подходящем уровне; ни один разрешённый capability не потерян.
- [ ] Условия обязательности медиа/промпта одинаковы в UI и API.
- [ ] Count=результаты и taskCount=запуски явно различимы, общая сумма соответствует обоим.
- [ ] Сворачивать advanced безопасно: выбранные значения сохраняются.
- [ ] Недоступность каталога, отключение модели, изменившаяся цена и частичная ошибка upload имеют восстанавливаемое состояние.
- [ ] Никаких «100% готово» и обещаний ETA, не полученных от сервиса.

## Тестовый пакет
Playwright: text→image, image→image, text→video, image→video, motion, metadata change, no models, 0 balance, duplicated click, keyboard-size viewport, long prompt, 200% text, two language/theme combinations. Captured payload должен точно соответствовать показанным сводке/материалам. Проверить существующие 300 journeys без изменения их финансового смысла. Для каждого нового сценария — positive и negative contract tests плюс screenshot до/после.

## Технические границы и observability
Не переписываем App целиком: выделять pure selectors/reducer/components по мере нужды, сохранять существующий API client. Model choice не дублируется в CSS/enhancer. Метрики: editor_open, scenario_selected, validation_blocked(reason), submit_requested, task_accepted; отделить UX time-to-submit от provider latency. Не логировать промпты, фото и initData. Выпуск малыми admin-preview PR, откат штатным revert; широкое включение только E10.
