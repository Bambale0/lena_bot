# [UX2-E05] Библиотека работ, просмотр, скачивание и безопасная публикация

Source: https://github.com/Bambale0/lena_bot/issues/214

## Цель и зависимости
Программа #209. Любой собственный результат можно быстро найти, открыть в исходном качестве, скачать и использовать дальше. Публикация — явное независимое действие. Приоритет P1. Базовая библиотека есть в #208; расширение статусов зависит от E04 (#213), повторное использование материалов — E01 (#210).

## Вертикальные срезы
- [ ] **E05.1 — история без ложной пустоты.** Пагинация и фильтры по типу/статусу/дате не ограничиваются первой случайной страницей. Сетевой сбой отличается от «работ пока нет». Частично загруженная история сохраняется с сообщением; кнопка повторяет нужный запрос, не весь платный workflow. Отдельно проверить дедупликацию при новых задачах между страницами.
- [ ] **E05.2 — полноэкранный просмотр.** Фото, видео, аудио и несколько результатов одной задачи имеют правильный renderer и original URL. Превью используется только как preview/poster. Перелистывание не сбрасывает фильтр/позицию/выбранный результат; закрытие восстанавливает фокус. Не автозагружать все тяжёлые ролики.
- [ ] **E05.3 — скачать оригинал.** Проверить текущий media resolver и допустимый Telegram download/open API. Кнопка означает реальный оригинальный файл, а не открытие уменьшенного thumbnail под видом скачивания. При запрете WebView — явный fallback с понятным действием. 403/404/expired URL обрабатываются без новой генерации.
- [ ] **E05.4 — использовать дальше.** «Создать похожее» создаёт новый обычный черновик только с разрешёнными параметрами; «Использовать как материал» выбирает конкретный результат и роль. Нельзя восстанавливать скрытый авторский prompt. Переход не отправляет POST генерации и не меняет исходную работу.
- [ ] **E05.5 — публикация и удаление публикации.** По умолчанию результаты приватны. Перед публикацией понятно, что увидят другие, включая промпт/референсы только при явном разрешении. Повторный click и задержанный ответ не вызывают toggle дважды. Снять публикацию не удаляет результат или историю. Сервер проверяет владельца.
- [ ] **E05.6 — организация и поиск.** Поиск по разрешённым пользовательским названию/дате/модели, фильтры, черновики отдельно от готовых. Избранное/папки вводить только при подтверждённом storage контракте; не рисовать рабочие кнопки без persistence. Empty states ведут в создание/сброс фильтра, но не навязывают оплату.

## Критерии приёмки
- [ ] Вчерашняя работа находится при объёме истории больше одной страницы.
- [ ] Все outputs одной задачи доступны; ready/private/published различимы.
- [ ] На видео не используется JPG как src, audio имеет controls.
- [ ] Скачивается исходный файл; причина fallback или отказа понятна.
- [ ] После Back сохраняются фильтры, scroll и выбранная карточка.
- [ ] Публикация не открывает скрытый prompt и не меняет права посторонней задачи.
- [ ] Ошибка API не выдаётся за пустую библиотеку или удаление данных.
- [ ] «Повторить» и «Опубликовать» не выполняются без подтверждённого действия.

## Негативные и регрессионные тесты
Backend: ownership, private/public boundary, deleted result, multiple outputs, expired signed URL, idempotent publish/unpublish. Browser: 0/1/1000 работ, partial page failure, duplicate pages, delayed refresh, image/video/audio, pagination+filter, клавиатура поиска, portrait/landscape, 320px, reduced motion. Download проверяется по href/response MIME/имени/содержимому, не только событию click. Реальный WebView проверяется отдельно.

## Производительность и диагностика
Ограничить число DOM-карточек/медиа-загрузок, сохранять позицию по стабильному task ID. Метрики history_load(duration/count/partial), result_open(media kind), download_attempt/outcome, publish outcome. Не логировать подписанные URL и тексты промптов. Максимумы загрузки и retention — из существующего configuration источника.

## Scope и выпуск
Сохранять действующую структуру GenerationTask/API, расширять только подтверждённые поля. Нельзя обещать восстановление физически удалённого результата. Срезы доставляются в admin preview; изменения ownership/publish всегда проверяются также на web/bot. Закрыть эпик после реального сценария find→open→download и проверки приватности, а не после появления карточной сетки.
