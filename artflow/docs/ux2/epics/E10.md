# [UX2-E10] Пользовательская проверка, управляемый пилот и выпуск UX2

Source: https://github.com/Bambale0/lena_bot/issues/219

## Цель и зависимости
Программа #209. Выпустить только тот объём UX2, который доказуемо удобен и безопасен; обеспечить наблюдаемый откат и не потерять незавершённые задачи/платежи. Приоритет P1. Протокол исследования и baseline можно готовить сразу. Включение для не-админов блокируется приёмкой выбранных E01–E09: материалы #210, редактор #211, повторы #212, lifecycle #213, результаты #214, навигация #215, деньги #216, WebView #217, контракты/диагностика #218.

## Вертикальные срезы
- [ ] **E10.1 — измеримый baseline.** Собрать конкретные жалобы и путь пользователя: экран, действие, ожидание, факт, устройство, безопасный task ID. Разделить UX-непонимание, серверный отказ и WebView-баг. Измерить исходную успешность подготовки/нахождения результата и время до подтверждения запуска; provider latency анализировать отдельно.
- [ ] **E10.2 — тест без подсказок.** Два раунда по 5–6 участникам разного опыта (предлагаемый протокол, не обещанный результат). Задания: первая генерация, повтор тренда, смена модели, поиск вчерашней работы, объяснение цены, возврат из оплаты. Фиксировать помощь модератора, ошибки и отказ; во время задания не обучать интерфейсу. Использовать тестовый контур и согласие на запись, не чужие реальные медиа.
- [ ] **E10.3 — закрытие дефектов и повторный раунд.** Каждая повторяемая проблема имеет issue, severity и тест. P0 деньги/данные и P1 невозможность завершить главный сценарий блокируют расширение. Низкий usability score нельзя скрыть косметическим апдейтом. Изменённые сценарии повторно проверяются с новичками, а не только разработчиком.
- [ ] **E10.4 — управляемые когорты.** Проверить существующий feature/control plane. Вводить server-authorized rollout cohort и kill switch с audit, без захардкоженного списка user IDs в bundle. Admin opt-in остаётся до проверки. Переход между старым и новым UI сохраняет task/payment IDs и совместимый draft; downgrade schema не уничтожает данные.
- [ ] **E10.5 — релиз и операционный smoke.** Feature branch→review→exact-SHA gates→штатный autodeploy→public health→asset hashes→container startup/logs→проверенные пользовательские сценарии. Сверять merge SHA, не предыдущий зелёный run. Provider operations выполняются только в согласованном тестовом бюджете; readonly health не доказывает успешную генерацию.
- [ ] **E10.6 — наблюдение и обратимый откат.** До расширения определить окно и пороги по baseline: ошибки, потеря draft, лишние invoices, неопределённые запуски, недоставка и latency. Любой duplicate charge/утечка/потеря подготовки останавливает rollout. Disable flag/revert не трогает ledger, не отменяет чужие задачи и не делает автоматический DB downgrade. Периодические проверки планировать только отдельным явным запросом.

## Критерии выхода
- [ ] Для выбранного scope нет открытых P0/P1 и непризнанных пропусков тестирования.
- [ ] Новички выполняют основные сценарии без объяснения интерфейса; итоговая цель успешности согласована после baseline, не придумана задним числом.
- [ ] Стоимость и требуемые входы поняты до платного действия.
- [ ] Есть реальные iOS/Android проверки, а не только viewport emulation.
- [ ] Серверные metadata/платежи/privacy согласованы с UI.
- [ ] Метрики разделяют UX, provider и delivery failures; privacy соблюдена.
- [ ] Откат протестирован на staging со старым draft и pending transaction.
- [ ] Release note перечисляет реально выпущенное и ограничения; ни один эпик не закрыт только по факту merge.

## Артефакты
Таблица сценариев и наблюдений, baseline/после с размером выборки, список дефектов, матрица платформ, проверенный commit/run/deploy, screenshots, smoke результаты, rollback runbook, решение о следующей когорте. Целевой результат — работающая студия, не обещание процента конверсии.

## Ответственность и последовательность
Технический исполнитель готовит evidence и рекомендации; владелец продукта принимает расширение аудитории. Идентифицированный текущий срез берётся в работу один; следующий начинается после обновления журнала и результатов проверок. Админский preview delivery допустим до закрытия всего E10, но называется именно preview, не финальным UX2-релизом.
