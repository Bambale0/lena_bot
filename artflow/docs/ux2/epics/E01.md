# [UX2-E01] Материалы и черновики без потери данных

Source: https://github.com/Bambale0/lena_bot/issues/210

## Родитель и цель
Программа #209. Пользователь свободно меняет модель, режим и экран; его фото, видео, описание и параметры не исчезают. До запуска видно, что будет использовано и что требует исправления.

Приоритет P1. E01.1 готов к выполнению после #208. Остальные срезы запускаются после указанных ниже результатов, а не после формального закрытия всего эпика.

## База и границы
В PR #208 есть owner-scoped sessionStorage обычных черновиков. Смена модели и режима ещё очищает массивы. Состояние дополнительных Seedance-референсов частично живёт в DOM enhancer: оно не считается покрытым сохранением React GenerationDraft. Нужна явная инвентаризация всех источников материалов. Не переписываем адаптеры провайдеров и не переносим скрытые данные трендов на клиент.

## Вертикальные срезы
- [ ] **E01.1 — неразрушающее переключение обычной генерации.** Смена модели/режима сохраняет исходный набор медиа и совместимые параметры. Несовместимые входы видны с причиной. В первой версии запуск блокируется до решения пользователя, а не молча урезает массив. Повторный переход к исходной модели возвращает тот же набор. Результат проверяется в DOM, storage и перехваченном POST.
- [ ] **E01.2 — активные и отложенные материалы.** После E01.1 пользователь может явно исключить файл из текущего запуска без удаления из черновика. Никакого автоматического выбора «первых N» при уменьшении лимита. Сборщик payload включает только выбранные активные входы; стоимость считается для того же снимка. Источник правды один, UI не хранит второй независимый список.
- [ ] **E01.3 — наглядная загрузка.** Превью, просмотр оригинала, имя/тип/размер и роль файла, повтор неудачной загрузки, удаление, замена. При частичном провале серии успешные загрузки не исчезают. Пока upload не завершён, нельзя запустить задачу или применить переключение к другому черновику. Поздний ответ не воскресает после явного удаления.
- [ ] **E01.4 — устойчивые ссылки.** Сначала проверить существующие asset IDs/ownership/TTL. Сохранять долговременный идентификатор, а не обещать бессрочность внешнего URL. При 403/404/истёкшей подписи получить новый разрешённый URL либо попросить повторную загрузку, сохранив описание. Не выполнять клиентские запросы к произвольным приватным сетям; серверный resolver валидирует URL и владельца.
- [ ] **E01.5 — версии черновиков и восстановление.** После E01.2–E01.4: явный draft ID, версия схемы, пользователь, источник сценария, время. Версионируемая миграция без раскрытия старых скрытых полей; обработка corrupt/quota/private-mode. Между аккаунтами нет восстановления. Между устройствами — только через разрешённый серверный контракт, не через перенос initData.
- [ ] **E01.6 — унификация дополнительных входов.** После инвентаризации заменить side-state enhancer для Seedance video/audio/role refs на типизированный черновик с контрактными тестами. Переносить по одному провайдерскому пути, временно сохраняя legacy adapter. Один формат mediatype/role не предполагается универсальным без проверки.

## Критерии приёмки эпика
- [ ] A→B→A сохраняет порядок и полный набор фото; видео и trim не исчезают.
- [ ] Лимит 4→1 не удаляет три фото и не создаёт платный запрос без явного решения.
- [ ] Неподдерживаемые photo/video/audio/character inputs не попадают в POST.
- [ ] Переключение во время upload имеет детерминированное поведение, не привязывает файл к чужому аккаунту или черновику.
- [ ] Reload/back/оплата/ошибка сети сохраняют обычную подготовку; ограничения хранения сообщаются честно.
- [ ] Удаление означает удаление, исключение из запуска означает сохранение; подписи различимы.
- [ ] ModelInfo является источником лимитов; никаких новых захардкоженных ID, тарифов или provider limits.
- [ ] Скрытые prompt/template assets отсутствуют в DOM, local/session storage и телеметрии.

## Проверки и диагностика
Unit: immutable transitions, A/B round-trip, modes, explicit zero/unknown limits, metadata skew, duplicate URLs, seed/IDs. Browser: два совместимых/несовместимых фиктивных провайдера, delayed upload, double-click, reload, account switch, 320px, light/dark. Контракт: UI и submit используют одинаковый compatibility result, отрицательный сценарий имеет 0 generation POST. Для новых событий — только draft correlation, action, counts и reason codes; не URL и не описание. Любая P0 утечка/двойное списание блокирует выпуск.

## Выпуск и откат
Только admin preview; старый UI/повторы трендов не меняются до своего среза. Каждый срез — отдельный PR с RED/GREEN, screenshot, точным SHA и production verification. E01.1 не закрывает E01. Долговременное хранение, cross-device и enhancer migration остаются открыты, пока не проверены отдельно.
