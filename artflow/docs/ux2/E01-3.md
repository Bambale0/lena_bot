# E01.3 - Per-file photo uploads

Tracking: #225, parent #210 / program #209. Base: 77db6e1.

## Delivered contract
Ordinary admin UX2 photo inputs have one canonical ReferenceMaterial list. Each item has a local ID and inclusion flag; optional upload state contains a unique operation ID, stage and source metadata. A replacement retains its original URL/name until the new operation succeeds. Queue is sequential; retry is explicit and only targets the failed file. Queued files are reserved in selection order. A per-file failure does not discard successes or skip remaining files.

Only ready included items enter the generation request projection. Pending work blocks launch; an included failure must be retried, reselected, excluded, deleted or a failed replacement explicitly reverted to its original. Excluding a failed file is not deletion. Model/parameter edits are locked during upload; cancellation remains reachable.

## Auth, transport and metadata
Authenticated GET /api/web/upload-media/policy exposes the existing server image byte limit and formats. Client validates size and signature before POST; server remains authoritative. Upload API accepts an optional AbortSignal and returns its existing URL/kind/content_type/size fields. No new asset ownership claim, prices, provider routes or billing policy. Browser upload transport is bounded at 60 seconds, with no automatic retries. Cancellation aborts the local request/attachment operation; it does not promise deletion of bytes already received by the server.

## State and recovery
File objects, object URLs and controllers exist only in the queue's memory. Object URLs are released after success/cancel/context change/unmount. Source results require the original authenticated owner, draft kind, material ID and operation ID; removed/superseded operations cannot reinsert an item. V3 persists typed metadata/stage without File/blob data. Restore converts unfinished uploads to a source-required state. V2 and V1 compatibility snapshots include ready inputs only. These browser writes are not a database transaction; write failures retain the last full snapshot and show the existing storage warning. Edits made by an older build are not automatically merged into the retained V3 snapshot.

## UI and verification
Visible preview, filename, measured bytes/MIME, queued/uploading/ready/error, selection, independent retry/reselect, replace, delete, keep original and cancel. Broken previews are recoverable UI errors, not deletion. All new primary file actions target at least 44 CSS pixels. Light/dark and narrow 320x568 browser coverage. No fake transfer percentages or generation ETA.

Unit/contract tests cover immutable transitions, late/duplicate completion, owner/template changes, timeout, source cleanup, V3 restore/older mirrors and policy/response validation. Playwright covers partial series, retries, replacement failure, interrupted reload, cancellation, navigation, duplicates, type/size/count/policy failures, exact POST selection and screenshot QA. Existing payment/privacy/smoke/user-journey tests remain required.

## Not in scope
Standalone video/audio/character parking and DOM-enhancer inputs, permanent media URLs/assets, cross-device drafts, backend atomic quote locks, provider uncertain-response reconciliation, physical Telegram iOS/Android and live paid requests. Preview remains admin opt-in. Release proof lives in #225/PR and the execution ledger, not a completion claim in this spec.
