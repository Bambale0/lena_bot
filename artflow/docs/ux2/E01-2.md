# E01.2 - active and parked photo references

Source issue: #222; epic #210; program #209. Baseline #221 / `a55e8e6f9f97e1255fe3b12d5c01e4608d0758f9`.
Status and final release evidence are authoritative in the GitHub issue, not inferred from this document.

## Delivered slice
Ordinary React generation drafts in admin UX2 gain an explicit per-photo checkbox. A checked photo is included in the next request; an unchecked photo stays in the draft. Delete is separate and removes the selected item by local id. Other users and template runners keep their current interface.

### Invariants
- No automatic subset selection, truncation, or activation on model changes.
- `referenceMaterials` is the sole canonical list once a draft uses selection. Every item contains local `id`, `url`, and boolean `included`. Canonical drafts keep `referenceUrls=[]`; request views derive their active URLs and contain no selection metadata.
- Existing legacy drafts continue to work and map to all-active items on the first selection action. Local item IDs are not backend asset ownership evidence.
- Duplicate filenames are not identifiers. Reordering matches full URL plus occurrence and preserves ids/states; appending an already parked URL does not activate it.
- Form cost/limits/required checks and request construction use `selectGenerationInputs`. The backend still validates ownership and admission.
- The active selection is copied before the request, editors are locked during upload/submit, and a synchronous command lock rejects duplicate same-frame starts.
- Selected drafts re-fetch the existing model catalogue before submitting. A changed price/capability set updates the UI and requires another explicit confirmation. Errors/timeouts stop before POST. The 15-second preflight timeout is only a finite UI transport guard; provider and payment retry policies do not change.

## Storage and compatibility
Normal v1 drafts remain readable. Selected drafts use a validated owner-scoped v2 snapshot. A generated v1 compatibility mirror contains only active refs, so reverting application code cannot restore a parked photo as active. The mirror is written before the full snapshot; partial/quota failure returns false and triggers the existing persistence warning. No storage operation is claimed atomic across keys.

A present but invalid/unknown v2 record is not overwritten or replaced by a stale v1 record. The last valid full snapshot is retained on failed writes. During full code rollback, changes made by the old version are not silently merged into v2; on upgrade, the preserved v2 snapshot remains authoritative. This is not cross-device synchronization or durable media storage.

Opening a template consumes only active inputs. Resetting it restores the owned ordinary selected draft, never the template prompt. The new-build legacy UI consumes active inputs only and preserves parked entries on return to preview.

## Files and responsibilities
- `src/lib/reference-selection.ts`: immutable selection and compatibility projection; metadata snapshot comparison.
- `src/lib/draft-storage.ts`: validated v1/v2 decoding and safe compatibility writing.
- `src/lib/draft-media.ts`: active-input compatibility and required-reference checking.
- `src/components/reference-selection.tsx`: explicit inclusion, separate deletion, disabled-state explanation and counts.
- `src/features/generation-screen.tsx`: one projected input set for display of limits/prices and canonical UI editing.
- `src/app/App.tsx`: upload integration, template restoration, request snapshot and metadata preflight.
- `tests/unit/reference-selection.test.ts`, `tests/ux2/active-materials.spec.ts`: state/storage/request/UI regressions.

## Scope explicitly not delivered
Parking source-video/audio/character inputs, enhancer-owned reference arrays, uploaded-file preview/lifecycle, server-side draft synchronization and the full editor redesign remain later slices. Provider-specific duration/role/enhancer values are not migrated by this change. No new backend schema, tariff, model route, payment, permission or production paid test. Metadata re-check is not a new atomic server-side quote lock: pricing changes between GET and POST still require the existing server contract and E07 work.
