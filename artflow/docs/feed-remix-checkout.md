# Artflow: первый повтор из ленты без лишних переходов

Публичная ссылка на фото/видео вида `/app?feed=<id>` или `/app?remix=<id>` открывает
**предзапусковую настройку именно этой работы**. Платный запрос до нажатия «Запустить повтор»
не производится. Ссылка на несуществующую/непубличную работу не должна открывать чужую карточку.

## UX сценарий

1. Пользователь открывает опубликованный пост в Telegram и нажимает
   «✨ Повторить со своим фото». Запасной путь «💬 Повторить в чате» сохранён.
2. Mini App сразу показывает исходную работу и одну форму: собственные фото, поле
   «Что изменить в образе» (необязательно, **до первой генерации**), модель,
   качество/формат/длительность.
3. На каждом изменении параметров отображаются **стоимость и баланс** из DB-тарифа.
   Смена количества изображений/разрешения/секунд инвалидирует прежнюю цену;
   скрытый исходный промпт в ответе /quote отсутствует.
4. Если кредитов мало, показывается рекомендуемый действующий пакет и
   кнопка «Пополнить здесь». Для выбранного пакета показываются только способы
   оплаты с действующей настройкой этого пакета. При нескольких способах можно
   выбрать нужный: карта/СБП — RUB, CryptoBot — USDT, Tribute — USD; для Lava
   итоговая сумма в RUB показывается на странице оплаты провайдера. Используется
   существующий /topup; форма остаётся открытой, статус баланса проверяется
   повторно. Оплата **никогда не запускает** генерацию автоматически.
5. После поступления кредитов пользователь явно нажимает
   «Запустить повтор · N 💋», затем открывается существующий экран задачи.
   Повторный быстрый клик не создаёт вторую задачу в том же окне.
6. Страница `/app`, открытая без ссылки, сохраняет обычное поведение. Сценарий
   использует исходное видео только у моделей с настоящим video input; MP4
   никогда не передаётся как фото-референс. Неподдерживаемое сочетание отклоняется
   при расчёте цены и повторно до списания.

## Backend / деньги / приватность

- `POST /api/v1/feed/{id}/remix/quote` и `POST /api/web/feed/{id}/remix/quote`:
  чтение публичного источника и текущей стоимости из БД; никаких списаний.
- POST /api/v1/feed/{id}/remix принимает необязательное change_request
  (до 800 символов). Исторический режим фото (до 9 октября 2026):
  для опубликованной оригинальной генерации с проверенным снимком входных
  референсов и выбранной image-модели backend берёт серверный промпт автора,
  убирает его оригинальные фотографии и результат, подставляет только
  фотографии пользователя и сохраняет исходный формат и качество, если
  пользователь явно не выбрал другие. При изменении текста добавляется
  лишь запрошенная правка. Публичный исходник не считается референсом и не
  занимает фото-слот; несуществующие/чужие URL не допускаются.
- Публикации без подтверждённых входных метаданных или производные работы
  продолжают проходить изолированный fallback-редактор сцены. Обычная
  генерация, Midjourney и видеогенерация остаются на прежних маршрутах.
  При недостатке пользовательских фото относительно оригинального рецепта
  запрос возвращает 422 до списания, вместо молчаливой подмены референсов.
- Промпт автора остаётся только на сервере, несмотря на использование
  во внутреннем платном запросе к модели. В generation записывается
  source_feed_gen_id и подтверждённый digest-контекст v4; текст промпта
  не копируется в историю, публичный API-ответ или ImageSession. Скрытое
  содержимое никогда не возвращается в quote; ошибки провайдера маскируются
  обычными правилами защиты контента. Серверное использование скрытого
  промпта не гарантирует, что сама генеративная модель не выведет его часть
  по просьбе пользователя или в результате prompt injection.
- Переключатель аварийного отката: FEED_ORIGINAL_RECIPE_ENABLED=false
  отключает новый маршрут без удаления уже созданных задач. По умолчанию
  включён; фоновые задачи, биллинг, idempotency и восстановление провайдера
  остались штатными. Для image-моделей стоимость count * цена модели
  определяется существующим серверным тарифом до списания.

- Повтор уже изменённой работы сохраняет безопасные правки по серверным
  versioned metadata, связанным с владельцем, исходным постом и точным промптом
  результата. Старый смешанный промпт без этой информации не переносится:
  пользователь получает объяснение до списания и вводит правки заново.
- Защита сохраняется у производных работ, включая работу самого пользователя.
  Подтверждения в боте и active/archive API сессий не показывают текст автора;
  исходный приватный текст не копируется в поля новой сессии. У исторической
  сессии без достоверного происхождения текста active/archive API скрывает
  промпт и сообщает: «Промпт недоступен для восстановления. Введите описание
  заново». Это может скрыть и старый собственный черновик, но не удаляет его
  серверный текст. Новые проверенные собственные тексты получают только
  серверный маркер `user_supplied`; клиент не может утвердить этот маркер.
  История с защищённой генерацией всегда имеет приоритет над маркером.
- Миграция `038_image_session_provenance` после `037_provider_routing_settings`
  добавляет nullable `image_sessions.prompt_provenance` без default/backfill.
  Исторические тексты, балансы и генерации не меняются. Повторная миграция
  после downgrade не восстанавливает потерянные маркеры автоматически:
  неизвестные записи остаются скрыты. При обычном откате приложения безопаснее
  сохранить неиспользуемую добавочную колонку, чем откатывать схему вслепую.
- Защищённые промпты скрыты в Telegram history/наследованных подтверждениях,
  подписях Midjourney и copy-text действиях. Ошибки провайдеров для защищённых
  работ показываются без сырых диагностик, которые могут повторить текст.
  Правила model-input для отдельных шаблонов marketplace/trends не изменены:
  их аудит не является частью гарантии изоляции персонализации ленты.
- Реальное списание и создание задачи выполняет существующий авторизованный
  backend; показанный quote не является отдельным источником тарифа.
- Пакеты берутся из действующих таблиц, способы оплаты — из настроек и
  существующих сопоставлений провайдера с конкретным пакетом. Quote возвращает
  `recommended_plan.payment_options` с `provider`, `amount`, `currency`;
  рекомендация без доступного способа не предлагается. Отсутствие этих метаданных
  не разрешает использовать первый глобальный `/payment-methods`. Для Lava
  `amount: null`: стоимость задаёт offer провайдера, RUB-цена из БД не выдаётся
  за сумму счёта. Новые тарифы или миграции не требуются.
- Отладочный лог quote включает ID публичной работы, ID пользователя, модель,
  стоимость и дефицит, но не пользовательское фото или скрытый промпт.

  `tests/test_image_session_provenance_migration.py` (SQLite + выделенный PostgreSQL CI),
  `tests/test_delivery_prompt_security.py`,
  `tests/test_safe_image_repeat.py`, `tests/test_repeat_callback_guard.py`.
- E2E: `webapp/tests/e2e/feed-remix-runner.spec.ts` и
  `webapp/tests/user-journeys/user-journeys-300.spec.ts`, включая deep link,
  изменение образа, отсутствие запуска до подтверждения и оплату при нуле
  с сохранением фото/параметров.
- В текущем облачном окружении Playwright не запускает Chromium: создание
  локального IPC socket отклоняется (`Operation not permitted`), включая
  повтор с расширенными разрешениями. Браузерные сценарии этой правки пока
  должен подтвердить GitHub CI; production-хост в этой проверке не использовался.
- Rollback: revert PR через штатный CI; добавочную nullable-колонку можно оставить
  неиспользуемой. Отдельный downgrade проверяется только в изолированной БД.
  Оплаченные задачи и исторические промпты не трогать.

## Ограничения

- На случай полной выгрузки WebView черновик (добавленные публичные URL
  собственных изображений и параметры, без исходного скрытого промпта)
  сохраняется в tab-scoped sessionStorage до 60 минут. После возвращения по той же
  ссылке он восстанавливается, после отмены или успешного запуска — удаляется.
  Этот сценарий нужно проверить на реальном мобильном Telegram после CI.
- Генерация у внешнего провайдера может остаться неопределённой после сетевого
  таймаута; состояние заказа и автоматическое восстановление должны подчиняться
  существующим механизмам provider reconciliation. Сам факт прохождения оплаты
  не служит разрешением повторить платный POST.

## Seedance 2.5: персонализация опубликованного видео

Seedance объявляет `text/multimodal`, а не отдельные `image/video` modes.
Персонализированный повтор учитывает его реальные automatic-input capabilities:
публичное исходное фото занимает первый image-reference, видео передаётся как
отдельный video-reference. Mode определяется существующим нормализатором по
фактическим входам. Скрытый авторский текст при этом не возвращается в контекст.

Для изменения опубликованного видео сервер добавляет явное намерение редактирования
к уже безопасному промпту. Произвольные дополнительные фото не объявляются
фотографиями личности или одежды: специализированные `identity_transfer` и
`content_edit` сохраняют свои отдельные проверенные правила.

До quote и повторно до списания используется существующая проверка исходника:
локально проверяемое видео, ограничения Seedance, включая 4–30 секунд, и округление
длительности вверх для тарифа из БД. Клиентские duration/control tokens не заменяют
измерение. Quote возвращает `source_video_edit` и `effective_duration_seconds`;
форма объясняет, что длительность/кадр берутся из источника и сколько секунд оплачивается.
Bot launch и regeneration используют ту же проверку до расчёта и списания.

На Neironych итоговый контракт содержит `omni_reference_task_type=edit` без полей
duration/aspect_ratio. На KIE это существующий multimodal-reference контракт с
`duration=-1`, `aspect_ratio=adaptive` и явной инструкцией редактирования, а не
несуществующее отдельное поле `edit`. Поставщик по-прежнему определяется действующей
маршрутизацией и защитой PR206; новых автоматических повторных отправок нет.

Исходное видео должно быть единственным эффективным video-reference, включая
ссылки в namespaced control tokens. Совпадающие ссылки дедуплицируются. Исторический
внешний/непроверяемый ролик отклоняется до тарифа/списания; новая скачивающая схема
для таких ссылок не добавляется. Качество сохранения личности и сцены проверкой кода
и моками не подтверждено.

## Автоматическая проверка неопределённого видео

Статус «Уточняем статус» означает, что проверка поставщика продолжается
автоматически. Уведомление больше не требует обращения в поддержку: бот, сайт
и Mini App сообщат о результате или подтверждённой ошибке через существующие
механизмы. Кредиты остаются удержаны до подтверждённого окончательного состояния;
повторная платная отправка или возврат по одному таймауту не добавлены.

Текущий upstream API возвращает `pending` для всех активных внутренних состояний
и не раскрывает признак принятого Argo-задания. Поэтому исчезновение ошибки из
`pending` не снимает защиту неопределённой отправки. Настоящий `done/failed`
по-прежнему автоматически завершает задачу и заменяет статус проверки.
Сам текст интерфейса не восстанавливает отсутствующий идентификатор upstream.
