# Artflow: первый повтор из ленты без лишних переходов

Публичная ссылка на фото/видео вида `/app?feed=<id>` или `/app?remix=<id>` открывает
**предзапусковую настройку именно этой работы**. Платный запрос до нажатия «Запустить повтор»
не производится. Ссылка на несуществующую/непубличную работу не должна открывать чужую карточку.

## UX сценарий

1. Пользователь открывает опубликованный пост в Telegram и нажимает
   «✨ Повторить со своим фото». Запасной путь «💬 Повторить в чате» сохранён.
2. Mini App сразу показывает исходную работу и одну форму: собственные фото, поле
   «Что изменить в образе» (необязательно, **до первой генерации**), модель,
   качество/формат/длительность.
3. На каждом изменении параметров отображаются **стоимость и баланс** из DB-тарифа.
   Смена количества изображений/разрешения/секунд инвалидирует прежнюю цену;
   скрытый исходный промпт в ответе /quote отсутствует.
4. Если кредитов мало, показывается рекомендуемый действующий пакет и
   кнопка «Пополнить здесь». Используется существующий разрешённый платёжный
   провайдер и /topup; форма остаётся открытой, статус баланса проверяется
   повторно. Оплата **никогда не запускает** генерацию автоматически.
5. После поступления кредитов пользователь явно нажимает
   «Запустить повтор · N 💋», затем открывается существующий экран задачи.
   Повторный быстрый клик не создаёт вторую задачу в том же окне.
6. Страница `/app`, открытая без ссылки, сохраняет обычное поведение. Сценарий
   работает для видео через пользовательское фото (image mode), не передавая
   исходный MP4 как фото-референс.

## Backend / деньги / приватность

- `POST /api/v1/feed/{id}/remix/quote` и `POST /api/web/feed/{id}/remix/quote`:
  чтение публичного источника и текущей стоимости из БД; никаких списаний.
- `POST /api/v1/feed/{id}/remix` принимает необязательное `change_request`
  (до 800 символов) и дополняет скрытый промпт автора, не раскрывая его через
  API. Для image-моделей стоимость нескольких вариантов учитывает `count`.
- Реальное списание и создание задачи выполняет существующий авторизованный
  backend; показанный quote не является отдельным источником тарифа.
- Пакеты/провайдеры берутся из действующих таблиц и /payment-methods;
  новые тарифы, жёсткие цены или миграции не требуются.
- Отладочный лог quote включает ID публичной работы, ID пользователя, модель,
  стоимость и дефицит, но не пользовательское фото или скрытый промпт.

## Проверка

- Backend: `tests/test_feed_remix_prelaunch.py`, `tests/test_webapp_routes.py`
  (относящиеся к повтору кейсы), `tests/test_callback_coverage.py`.
- E2E: `webapp/tests/e2e/feed-remix-runner.spec.ts` и
  `webapp/tests/user-journeys/user-journeys-300.spec.ts`, включая deep link,
  изменение образа, отсутствие запуска до подтверждения и оплату при нуле
  с сохранением фото/параметров.
- Локальный Playwright на production-хосте не запускает Chromium из-за
  отсутствующей системной libatk; браузерные тесты должен подтвердить GitHub CI.
- Rollback: revert PR; схемы БД не меняются, оплаченные задачи не трогать.

## Ограничения

- На случай полной выгрузки WebView черновик (добавленные публичные URL
  собственных изображений и параметры, без исходного скрытого промпта)
  сохраняется в tab-scoped sessionStorage до 60 минут. После возвращения по той же
  ссылке он восстанавливается, после отмены или успешного запуска — удаляется.
  Этот сценарий нужно проверить на реальном мобильном Telegram после CI.
- Генерация у внешнего провайдера может остаться неопределённой после сетевого
  таймаута; состояние заказа и автоматическое восстановление должны подчиняться
  существующим механизмам provider reconciliation. Сам факт прохождения оплаты
  не служит разрешением повторить платный POST.
